# Release updates

Use semantic versions: patch for fixes, minor for new features, major for incompatible changes. Use the release date in Asia/Singapore, formatted as 10 Nov 2026.

Keep GitHub and Sites on the same version and date. Update About in help.html, app information in index.html, CHANGELOG.md, and the service-worker VERSION on every release. Add short user-facing release notes to both About and app information. Export schema versions are separate and must remain compatible with Report Studio.
